# 问题、方法与数据可行性的研究闭环

2026-10-29。对应 [Issue #17](https://github.com/flat-git/eiqas-deerflow/issues/17)。本次为 v0.1 开发中的研究设计迭代，不发布新版本、不迁移旧项目。

## 产品行为

面向制造业与商业定量问题，先通过有限轮对话明确决策用途、对象、范围和数据条件。Agent 从业务、方法和数据视角提出成熟可行的候选方法，不固定数量。方法说明依据、计算逻辑、适用条件、关联问题与预期图表。

确认之前允许搜索、取得公开原件、解析、登记候选与冻结数据以检查可行性；这些动作不会启动正式计算。用户在原生对话上传的内部表格、专家材料或已取得研报可通过 `eiqas_import_upload` 从当前用户/线程的 uploads 目录复制为原件，保留哈希，不伪造公开 URL。上传原件经过同样的解析、候选核对和冻结数据检查。

数据要求按 public/internal/expert/commercial/collection/unknown 分类，记录字段、指标、观察粒度、期间、单位、渠道、缺失影响及替代建议。获取进展与设计分开保存：渠道建议、已有线索、公开样本核实、实际取得、无法取得、访问受限、口径/质量待核对。缺口类型包括缺值、粒度、期间、定义、单位、质量、访问与覆盖。

公开样本已核实必须关联实际取得原件中的准确摘录和定位。内部、专家、商业数据不接受“可能取得”的样本承诺。声明量化数据已取得须有冻结数据集，覆盖要求中的指标，并检查原件、提取和数据集完整性。结构核查不证明语义上的适用性或样本代表性。

用户可在方法/数据面板说明“只有这些数据”，作为可见对话发送，要求重拟方案。每个原问题保留为可以回答、部分回答或当前无法判断；范围调整明示，候选方法可不选。背景指标不能自动代替主要研究问题。最终确认前须至少有一项直接回应可回答问题的量化方法，且选中方法的数据可行性有实际依据。

## 确认与执行

新建研究的 workflow_version 为 2，由服务端设定，客户端不能绕过。最终确认绑定当前问题和完整设计的哈希，保存确认时的可得性快照。问题、方法、约束或数据要求实质变化使确认失效。后续取得数据和更新评估不改变批准哈希。

正式运行还检查选中的具体 method_id、对应 operation，以及输入的来源/指标与该方法数据要求的关联；同类方法有多个时必须显式选择。公开样本可支持确认获取可行性，但正式运行前仍须登记实际可计算数据。新发现的数据缺口或失效依据阻止继续计算、交付。

关键数据、定义冲突、OCR 存疑和范围变更可通过 `eiqas_request_input` 登记问题、影响和数据要求。前端显示待答复卡片，答复通过专用 HTTP 动作保存，Agent 没有代答接口。修改方案不能消除尚未回答的问题。范围变更答复撤销旧批准；保持口径的普通补数答复无需额外批准，后续实际修改设计仍需重新确认。

`eiqas_read_planning` 返回可得性和由业务记录计算的下一步。工作台的“确认/继续”动作标记原生推进回合；若模型在保存/评估草稿后仍有常规修复，或在正式研究仍有工作时提前结束，中间件在同一个 DeerFlow run 中最多续行两次。实际待人工答复或计算仍在运行时不续行。达到上限明确说明尚未交付，不把原生回合终止当成研究成功。普通对话和阅读追问不被强制转为执行。

保留 DeerFlow 原生线程、模型、SSE、取消、工具循环和沙箱。没有新建 Agent 调度器，也没有修改 Harness 核心。

## 接口

- `GET /api/eiqas/research/{rid}/planning`：研究设计可行性与下一步。
- `POST .../data-assessments`：追加绑定数据要求哈希的可得性评估。
- `POST .../input-requests/{request_id}/reply`：用户答复，核对请求哈希，拒绝过期/重复答复。
- 原有 plan/confirm/run/result 接口继续共用业务层；工具新增 read_planning、assess_data、request_input、import_upload。
- 交付履行申报忽略未选候选，不将其自动变成完成；选定计算方法必须引用该 method_id 的真实运行。

## 验证与限制

新增合成制造业测试覆盖数据不足后的可行重拟、公开线索与实际取得区分、内部数据依赖、方法/输入绑定、范围变化、跨研究与过期引用、关键追问、上传路径及原生有界续行。组件测试覆盖分类、无法回答的问题和可见的数据边界对话。数值/导出合成验收先保存实际数据，再显式模拟最终确认，仅在独立验收研究中使用。

当前实现提供确定性契约和有限的原生续行。方法是否真正适用于业务、样本是否代表完整数据、解释和洞察是否受证据支持，仍需真实模型流程验证。本次不将 AI 履行申报称为独立语义审计，不将通过结构/数值测试称为完全自主研究成功。Issue #17 的真实无人代修研究和实际试用未完成前保持开放。

已有实验研究保留原记录以供查看和回归，不自动补写新版研究设计。本迭代的产品验收以新建研究为准。
