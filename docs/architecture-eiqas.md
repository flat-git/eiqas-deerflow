# EIQAS 业务扩展

产品基于固定的 DeerFlow v2.1.0，在其原生线程、模型、流式事件和沙箱上运行。`backend/packages/eiqas-research` 是独立 Python workspace 包；插件通过公开 `deerflow-extension-api` 注册服务、路由与模型请求中间件，没有修改 Harness 循环。

## 研究与确认

一项研究绑定一个线程，数据库强制线程唯一。业务数据保存在独立 SQLite，资料目录按线程隔离。`/api/eiqas/research` 提供创建、读取和列表，研究下的 `question`、`plan`、`confirm`、`stage`、`scope` 与 `events` 提供相应操作。

方案包含问题、带理由的方法、所需数据、假设、预期产出及限制。方案内容和保存时的原始研究问题 SHA-256 一同生成方案哈希；分析问题允许重述，确认不依赖两段文字逐字相等。工作台确认请求必须带上预览时的哈希。问题或方案变更后，执行门禁拒绝使用旧确认。完全相同的保存保留确认。确认只暴露为网页操作，Agent 工具没有该能力。

五个阶段可往返。执行状态、可以回答的问题和数据缺口分别保存，不计算总体研究完成百分比。每次业务更新与事件在同一 SQLite 事务提交；按序号读取事件可恢复刷新后的状态。Agent 会话、运行取消和 SSE 仍属于 DeerFlow。

## 依赖与运行

`config.eiqas.example.yaml` 使用原生模型适配和工具声明。模型 ID、地址及凭据由部署者在本地环境配置，不写入研究或 Git。`ResearchContext` 仅为关联研究的模型请求补充当前业务上下文，不创建新的 Agent 或调度器。

业务 I/O 使用同步领域方法；FastAPI 同步路由和原生同步工具在线程池执行。插件生命周期与异步模型钩子使用 `asyncio.to_thread`。单 Gateway worker、单用户为本版边界。

## 实施与验收状态

研究记录和确认的首批 14 项离线测试已通过。界面、实际模型推进、OCR、计算和交付分阶段实现与验收，不能从这些契约测试推定端到端完成。以 `docs/v0.1-acceptance.md` 和 GitHub Issue 中的实际证据为准。

## 原件、计算与交付

`evidence.py` 保存原件、取得失败、定位提取、候选值与人工纠正；数据集冻结每条来源、定位、口径和原值。单位与期间冲突不自动合并，下限/上限/区间不当精确值计算。

默认 `web_fetch` 直接取得公开原件并复用原生AIO解析；请求URL与最终取得URL同时保存，文本和链接均有定位。没有第三方正文服务的默认依赖。公网连接固定到校验过的地址，重定向重新检查；代理合成DNS仅使用固定公共DoH解析复核，不增加私网白名单。

候选登记使用原始数字和单位，数据集归一化支持元/千元/万元/亿元。`eiqas_withdraw_observation` 只撤回尚未人工核对且不可用于计算的错误登记，保留原文/原值/原因；没有人工批准能力。`eiqas_read_records` 分页读取当前线程已有记录和运行，提取文本仍由定位检索工具读取，避免上下文压缩后重复采集。

`analysis.py` 只登记真实AIO执行回执；输入、脚本、日志、结果JSON/CSV和检查均有hash。未确认方法不执行，取消/重启不把迟到结果提升为成功。内建方法使用DuckDB/Pandas/Scipy并独立复算；生成Python方法与独立检查程序在分析沙箱分别执行，每个数值结果单元格都须有独立期望值与本次输入依据。

`reports.py` 解析真实结果单元格、定性摘录及出处，`exporter.py` 从同一成果生成四类交付。ZIP仅按显式名单收集被引用原件、提取、冻结数据和计算材料。ECharts固定资源及第三方许可证随Python包提供，不依赖外部CDN。

前端 `/research` 采用独立暖白/深绿布局，复用原生权限、线程、模型选择、输入和SSE。正文、对话和阅读区域在固定视口内分别滚动；数据查询按研究ID隔离。成果绑定结果ID，重算创建新运行，当前阅读不被后台更新替换。
