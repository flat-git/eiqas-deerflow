# 中断后继续研究

对应 Issue #19。修复目标是停止实际任务后恢复原线程，保留对话、研究、方案门禁和已经取得的原件。

## 原因

用户点击停止后，RunManager 立即登记 `interrupted`，但原生 worker 仍持有 `finalizing` 屏障直到工具退出及检查点收尾结束。该屏障防止新旧运行同时写同一线程，不能根据已中断状态直接清除。

原 EIQAS 解析/计算使用同步沙箱命令，工具取消后 shield 等待整个命令结束，没有通知实际进程。AIO 原同步方法忽略 timeout 参数，HTTP/空闲等待上限也不等于进程硬超时。真实 PDF/OCR 在取消后仍运行，期间新请求得到 409；该次原生取消到 worker 退出间隔接近九分钟。旧执行随后恢复可用，没有删除运行或改写数据库。

## 修复

- AIO 新增 `execute_command_cancellable`：每个任务独立显式会话，异步提交，短请求轮询。取消只终止本任务，回收本会话；失败不自动重放命令。服务端 `hard_timeout` 与本地截止时间共同限制执行。
- EIQAS 的 `execute_job_async` 给 offload 传入取消事件。首次或重复取消均排空同一个任务；排队和上传阶段检查取消，取消后不再启动执行、下载或提交成功结果。
- 保留原生运行管理、流式事件、检查点与 finalizing 语义。实际计算仍受批准及结果校验约束，迟到结果不能把取消提升为成功。
- 网页停止保留 SDK 的流中断，并等待原生 `cancel(wait=true)`。等待期间显示“正在停止”，阻止同线程再次发送；重复点击复用同一次停止，切换研究不继承旧线程的等待状态。

这不改变已有通用 bash 的执行语义，也不为网络故障承诺瞬时结束。控制面请求有短超时；终止或会话回收失败记录日志，远端硬超时仍是最后的约束。阶段性 HTTP 409 对真实仍在执行/收尾的任务继续有效，不能通过忽略互斥解决。

## 验证记录

- 取消能力测试在实现前失败；修复后涵盖预先取消、独立会话、硬超时、未知终止状态、输出/退出码、重复取消、排队取消及原生线程继续。
- 真实 AIO 合成进程：取消约 1.11 秒，父/子进程均退出，随后命令成功；2 秒硬超时得到明确失败而非成功结果。
- 可复验脚本：`uv run --project backend python scripts/acceptance/cancellation.py --base-url <测试沙箱API>`。使用已经启动的 AIO，创建自己的合成进程/定位文件并回收；不访问模型凭据，不修改研究记录。
- DOM 回归核对服务端停止确认前仍 busy、同线程发送被阻止、切换研究不受影响。
- 完整测试、部署和浏览器结果在 `eiqas-development.md` 记录。这里的运行恢复不表示真实研究或 v0.1 发布验收完成。
